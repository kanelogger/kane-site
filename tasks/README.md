# 任务与恢复

多步骤、跨会话任务从 [模板](../templates/task.md) 创建 `tasks/YYYY-MM-DD-short-name.md`。只写可公开的信息；私有目标和原始日志放被忽略的 `.agent-local/`。简单一次性修改无需任务文件。

## 恢复顺序

1. 读取根 `AGENTS.md`，执行 `git status --short`、`git log -5 --oneline`。
2. 找到 `tasks/` 中 `Status: active` 或 `Status: blocked` 的任务；多个任务并存时按用户本轮目标选择，禁止仅按文件时间猜测。没有匹配任务时先根据本轮目标建立记录。
3. 检查记录的基线、未提交文件和证据。对照当前 diff 与源码，提交变化后旧检查标为需重跑；摘要中的“完成”不能代替验证。
4. 环境变化或新 checkout 运行 doctor，定位阻塞原因。按记录的下一步继续，保护其他任务的改动。
5. 中断、阻塞、阶段完成或交付前更新任务。已完成任务设 `Status: complete`，移至 `tasks/archive/`；保留脱敏结果、必要决策理由与复现命令。

记录的是当前事实与交接，不复制聊天历史、不保存长期凭据、不自动添加用户级规则。临时选择不升级为长期约定；会影响未来任务的决定写明原因、来源和适用范围。后续替代决定需要链接原记录并标明失效条件。

没有独立验证的项目明确写“未验证”。本地日志不是共享证据的唯一来源；日志不可获取时，新会话应可用记录中的命令重建检查。
